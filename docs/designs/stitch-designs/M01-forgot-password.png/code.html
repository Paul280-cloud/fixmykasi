M1 Forgot Password Specification & Compliance Notes

Ordered Layout & Modal Pattern Enforcement (PRD 8.2)

  • Modal Architecture: Built strictly as a bottom sheet modal on mobile devices (border-top-left/right-radius: 24px) over a dimmed parent view (S3 Log In) with an accessible drag handle.
  • Header & Content Ordering:
    1. Title: verbatim "Reset your password" in 20px bold Heritage Brown (#531A17).
    2. Body Text: verbatim "Enter your email and we'll send you a link to choose a new password." in 14px secondary text (#5C5650).
    3. Email Field: required email input (height 48px, placeholder "you@example.com").
    4. Primary Button: 48px height "Send link" in Coat of Arms Green (#005D28).
    5. Text Button: 44px min height "Cancel" in Heritage Brown (#531A17).
  • Desktop Adaptation: As specified in PRD Section 8.2 ("a bottom sheet on phones, centred 480 px wide on desktop"), Frame 6 provides the 480px centred dialog specification with identical copy and actions.
  • Visitor Chrome: S3 persistent bottom tab bar displayed with "Log in" active in Coat of Arms Green.

State Coverage & Business Rules Verification

  • State 1 (Normal & Empty): Initial empty form ready for email entry with autofocus and valid email type.
  • State 2 (Loading): "Send link" button dynamically displays an animated circular CSS spinner with text "Sending link..." and disabled inputs to prevent duplicate API dispatches.
  • State 3 (Error): Features both the verbatim general error banner ("Something went wrong. Try again.") and the exact field validation error message ("Enter a valid email address.") on malformed input.
  • State 4 (Offline): Top charcoal grey offline banner ("You're offline. Changes will not be saved.") and disabled "Send link" button.
  • State 5 (Success): Displays verbatim PRD message: "If this email has an account, we've sent a reset link.", and transforms the primary action button to "Done" (which closes M1 back to S3).
  • Sample Content: Seed email address thandeka.m@example.com used across states.
MISSING ITEMS & TODOS: All required elements, order, labels, states, and copy were fully provided in PRD Section 8.2. No TODO placeholder boxes were required.
