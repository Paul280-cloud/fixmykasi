S12 Set New Password Specification & Compliance Notes

Ordered Layout & Chrome Enforcement (PRD 8.2)
  • Header: Heritage Brown (#531A17) top bar with white back arrow (≥44px touch target) and white title "Choose a new password", finished with persistent 3px Gold (#D8A851) underline.
  • New password field: Required password input with 48px height, eye show/hide toggle button (44×44px tap target), and placeholder "At least 8 characters".
  • Confirm password field: Required password input with 48px height, eye show/hide toggle button, and placeholder "Type it again".
  • Primary button: Full-width 48px "Save password" in primary Coat of Arms Green (#005D28).
  • Tab Bar: Persistent bottom tab bar in visitor mode (Faults, Log in active).
State Coverage & Business Rules Verification
  • State 1 (Normal): Empty clean form ready for password entry.
  • Empty State: Explicitly marked as not needed per PRD Section 8.2.
  • State 2 (Loading): "Save password" button dynamically displays an animated circular CSS spinner with disabled input state.
  • State 3A (Expired / Used Error): Alert banner with verbatim copy: "This link has expired. Request a new one." and primary button "Send new link" (routing to M1).
  • State 3B (Validation & General Error): Inline field errors with verbatim copy "Use at least 8 characters with a letter and a number.", mismatch error "The passwords don't match.", and general error "Something went wrong. Try again.".
  • State 4 (Offline): Top charcoal grey banner "You're offline. Changes will not be saved." with disabled "Save password" button.
  • State 5 (Success): Direct transition to S3 Log In displaying the verbatim toast: "Password changed. Please log in.".
MISSING ITEMS & TODOS: All required elements, order, labels, states, and error messages were fully provided in PRD Section 8.2 and 8.3. No TODO placeholder boxes were required.
